# PZT provisional calibrated analysis

The active analysis is **provisional, not final validated experimental results**.
All active outputs are in `provisional_calibrated/`. Earlier native-unit
figures remain historical diagnostics and are not regenerated by this workflow.
Original data remain unchanged.

## Confirmed inputs and working assumptions

The experimenter confirmed 5.05 micrometres/pixel, pulse separation 25
microseconds, upward spray, upward-positive axial U and rightward-positive
transverse V. The conversion is 0.202 m/s per pixel displacement per pair.

The following are explicit user-authorized working assumptions, not
independently verified exporter conventions:

- `us/vs` are horizontal/vertical pixel displacements per image pair. Their
  means reproduce exporter STATISTICS/U,V; this does not define their upstream
  smoothing/replacement or their relation to `u/v`.
- Retain the stored vertical sign: U = +0.202 vs and V = +0.202 us. No ZNMF
  reversal is inherited and no sign is chosen to make the mean positive.
- Exported coordinates are pixels. Scale once by 0.00505 mm/pixel. Display
  transverse y horizontally and axial x vertically. Exported (0,0) is the
  image-reference origin; no outlet centre has been established.
- Use the **finite-pair population**, with both components finite. No flag
  code is treated as physically accepted or rejected. Counts, means and RMS
  for each code are separate selection-sensitivity diagnostics.

`config/analysis.json` is the single configuration source. It records the
assumptions, evidence, source components, conversion factors, mappings, origin,
stations, profile rows, representative frames, vector indices and output path.
The run saves an exact copy as `provisional_calibrated/configuration_used.json`.

## Orientation evidence inspected

The ZNMF analysis applies a reversal to its horizontal downstream component;
that does not establish a PZT vertical reversal. The nearby VMARF TIFF images
are 2048x1536 calibration-target/droplet images without a documented link to
this 319x80 HDF5 field or a software vector display. Assembly.png is a module
illustration. They do not resolve the sign of vs. The direct raw-HDF5 comparison
and line-level ZNMF references remain in `results/znmf_comparison.md` and JSON.

## Run and regenerate

From the PZT_droplets workspace root:

```powershell
.\.venv\Scripts\python -m PZT_Atomiser_Analysis.analysis.pipeline --config PZT_Atomiser_Analysis/config/analysis.json
```

Open `notebooks/Spatial_maps.ipynb` with the workspace `.venv` kernel. It calls
reusable module functions and produces the actual figures. To build and execute
that notebook from the command line:

```powershell
.\.venv\Scripts\python -m PZT_Atomiser_Analysis.analysis.build_calibrated_notebook
```

`analysis/build_notebook.py` forwards to that builder. The executed notebook is
also copied into the provisional result directory. Dependency versions are in
`requirements-lock.txt` and each run's `results/software_versions.json`.

## Definitions and validation

The conversion is applied once to instantaneous samples before calculating
all means, RMS, covariance, correlation and speed statistics. Population
moments use denominator N, not N-1. Zero-variance correlation and statistics
with fewer than two pairs are masked. Missing vectors are never zero-filled.
Magnitude of the mean vector and mean instantaneous speed remain distinct.

Stations are configured native grid nodes, not pooled ROIs or a claimed
physical centreline. Profiles use native rows without interpolation. PDFs are
full-support empirical histogram densities with common bins per quantity
across stations; CDFs are exact empirical staircases. No KDE tails, frame-
independence confidence intervals or turbulence interpretation are claimed.
No reverse-flow fraction is reported while axial sign is unverified.

Checks include independent station statistics for each population, converted
stored-mean consistency, flag-count partition, nonnegative variance,
correlation bounds, mean-speed inequality, CSV/NPZ agreement, histogram
normalization, export completeness/dpi and a synthetic sign/covariance test.

## Resolve conventions without rewriting the analysis

The internal plotting basis is [transverse V, axial U]. `components` selects
source datasets. `component_mapping` maps those into this basis;
`coordinate_mapping` maps exported coordinates into [transverse,axial].
`transform` is a common orthogonal basis change applied to BOTH positions and
velocities. `origin` is subtracted in scaled exported coordinates before these
coordinate transforms.

A later common reflection updates coordinates, vector arrows and recomputed
covariance consistently. An exporter-only component correction can differ
from the coordinate correction if the exporter already reflected coordinates;
document that evidence rather than reflecting coordinates twice. Change the
configuration and rerun to regenerate every result and the exact-vector sheet.
No derivatives are calculated in this run; future derivatives must use the
same transformed Cartesian basis. General rotations are rejected for native-
row profiles that would no longer be constant-axial cuts.

Keep scales and working-assumption text consistent when evidence arrives.
If storage is confirmed already calibrated, set the appropriate scale (1 for
m/s) and document `verified_scale_override_reason`; the guard then permits
that explicit override. Coordinate scale must also match verified storage.
The output directory can remain the same to replace the provisional run.
